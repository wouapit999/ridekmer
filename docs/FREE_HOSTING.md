# Free hosting (no paid plan)

RideKmer can run entirely on free tiers while it is being assembled and tested. The pattern
is the same on every free host (ADR-038):

| Need            | Free service                                                         | Notes                                                          |
| --------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| Application     | Vercel Hobby **or** Render free web service                          | see the two paths below                                        |
| PostgreSQL      | Neon free tier (0.5 GB) or Supabase free tier                        | copy both the pooled and the direct connection string          |
| Files (uploads) | Vercel Blob (1 GB on Hobby) or Cloudflare R2 (10 GB)                 | `STORAGE_PROVIDER=vercel-blob` or `s3` with the R2 S3 endpoint |
| Scheduled jobs  | GitHub Actions (`.github/workflows/cron.yml`)                        | free on a public repository; `CRON_MODE=external` on the host  |
| Rate limits     | in-process memory (`RATE_LIMIT_BACKEND=memory`) or Upstash free tier | memory is fine while there is one instance                     |

The scheduler lives in GitHub, so it keeps running even when a free host sleeps: each call
wakes the host, waits up to a minute for it, then runs the job.

## Path A — Vercel Hobby (simplest)

Vercel builds Next.js with zero configuration. The Hobby plan only refused the **sub-daily
cron schedules**, which `vercel.json` no longer contains.

**Honest limit:** Hobby is for personal, non-commercial use. It is acceptable while you
assemble and test; before taking real bookings, move to Vercel Pro (about 20 USD a month) or
to Path B.

1. vercel.com → Add New → Project → Import `wouapit999/ridekmer` → Framework "Next.js"
   (detected) → leave Root Directory empty → do **not** deploy yet; open Environment
   Variables and add:

   ```
   APP_ENV=production
   NEXT_PUBLIC_APP_URL=https://<project>.vercel.app
   BETTER_AUTH_URL=https://<project>.vercel.app
   AUTH_TRUSTED_ORIGINS=https://<project>.vercel.app
   DATABASE_URL=<Neon pooled URL>
   DIRECT_DATABASE_URL=<Neon direct URL>
   BETTER_AUTH_SECRET=<openssl rand -base64 48>
   APP_ENCRYPTION_KEY=<openssl rand -base64 32>
   APP_ENCRYPTION_KEY_ID=v1
   CRON_SECRET=<openssl rand -hex 32>
   CRON_MODE=external
   RATE_LIMIT_BACKEND=memory
   STORAGE_PROVIDER=vercel-blob
   ALLOW_DEMO_SEED=false
   ```

2. Storage → Create → Blob → connect it to the project; Vercel adds `BLOB_READ_WRITE_TOKEN`.
3. Deploy. The first build takes about 2 minutes. The project URL replaces `<project>` above;
   update the three URL variables and redeploy once.
4. Apply the migrations and the reference data. Vercel never runs them; the easiest way is
   the **Database** GitHub workflow: add the repository secret `DIRECT_DATABASE_URL` (Neon
   direct, non-pooled URL), then _Actions → Database → Run workflow_ with migrate and seed
   ticked. The same workflow can create the first administrator (step 6). From a machine
   with Node 22 the equivalent is:

   ```bash
   DIRECT_DATABASE_URL="<Neon direct URL>" pnpm db:migrate:deploy
   DATABASE_URL="<Neon direct URL>" ALLOW_DEMO_SEED=false pnpm db:seed
   ```

5. GitHub → repository → Settings → Secrets and variables → Actions → New repository secret:
   `CRON_TARGET_URL=https://<project>.vercel.app` and `CRON_SECRET=<same value>`. Then
   Actions → "Scheduled jobs" → Run workflow → `housekeeping` to test it.
6. `curl -s https://<project>.vercel.app/api/health`, then create the first administrator:
   set `EMAIL_PROVIDER` (resend or smtp) with its credentials and `EMAIL_FROM` on Vercel,
   redeploy, and run the **Database** workflow again with only _bootstrap_admin_email_
   filled (or `POST /api/admin/bootstrap`, see `docs/OPERATIONS_RUNBOOK.md`). The temporary
   password arrives by e-mail; sign in, change it and enable TOTP.

## Path B — Render free web service (no non-commercial clause)

Render builds the `Dockerfile` (`render.yaml` is a blueprint for the service). The free
instance sleeps after 15 minutes without traffic and wakes in about a minute; the GitHub
scheduler tolerates that. Render's free PostgreSQL expires after 30 days, so use Neon.

1. render.com → New → **Blueprint** → connect `wouapit999/ridekmer`. Render reads
   `render.yaml`, creates the `ridekmer` web service on the free plan and prompts for the
   variables marked `sync: false` (URLs, database URLs, encryption key, S3/R2 credentials).
   `BETTER_AUTH_SECRET` and `CRON_SECRET` are generated by Render; copy `CRON_SECRET` from
   the service's Environment tab afterwards for GitHub.
2. For files, create a Cloudflare R2 bucket (free 10 GB): R2 → Create bucket → Manage R2 API
   tokens → Object Read & Write → use the S3 endpoint `https://<account-id>.r2.cloudflarestorage.com`,
   region `auto`, and the token's key pair as `S3_*` variables.
3. Deploy; the first Docker build takes 5–8 minutes. The service URL is
   `https://ridekmer.onrender.com` (or similar); set the three URL variables to it.
4. Migrations and seed from your machine, exactly as in Path A step 4.
5. GitHub secrets `CRON_TARGET_URL` and `CRON_SECRET`, as in Path A step 5.

Limits to know: 750 free instance-hours per month per workspace (one always-wakeable
service fits), 512 MB RAM, a cold start of about a minute after idling, and no persistent
disk on the free plan (hence R2).

## When to leave the free tiers

- Real customers or payments: Vercel Pro, Render Starter (7 USD a month, no sleep) or
  Railway Hobby; keep GitHub Actions as the scheduler or switch to `CRON_MODE=in-process`.
- More than one instance: Upstash for rate limits, S3-compatible storage, and the scheduler
  on one place only.
